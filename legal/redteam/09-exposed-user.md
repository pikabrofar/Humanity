# Red team 09: the user whose mic, camera or meeting data was exposed

Persona: someone whose raw audio, transcripts, voiceprints, eye data or screenshots leaked by accident. The cause could be a backup, a stolen laptop, a crash, a clipboard, a log or a cloud AI call.
Scope: code at commit 1f611aa, read-only. I also listed file modes under `~/Library/Application Support` on this dev Mac. I did not read any file contents. Not a lawyer. Nothing here says the app is "safe" or "compliant". Items for an attorney are marked **[ATTY]**.

## Where the data lives

All of it is unsandboxed (no `.entitlements` file in the repo). Directory and file modes below were observed on this Mac.

| Data | Path | Code |
|---|---|---|
| Meeting audio, mic.m4a and system.m4a (call audio), plus recording.json, meeting.json (transcript, speaker centroids, consent timestamp), summary.json | `~/Library/Application Support/Humanity/Meetings/<date>/` | `MeetingRecorder.swift:24,89`; `Meeting.swift:96` |
| Voiceprints (embeddings plus names), in `profiles.json` | `…/Humanity/VoiceProfiles/` | `VoiceProfileStore.swift:65,188-192` |
| Dictation and note audio (`<uuid>.m4a`) and transcripts (`<uuid>.json`) | `…/Murmur/Recordings/` | `RecordingStore.swift:14-32` |
| Gaze calibration. It holds `GazeFeatures.appearance`, the equalized eye-patch pixels (PRIVACY.md says "10x6-pixel eye crops"), plus head pose and face position. It was 1.8 MB here. | `…/OculOS/calibration.json` | `Persistence.swift:69,114-122`; `GazeFeatures.swift:26-28` |
| Gaze recordings (JSON) and optional full-screen PNG, default off | `…/OculOS/Recordings/` | `RecordingStore.swift:54-86`; `AppModel.swift:54,303` |

| Provider API keys | login Keychain, never on disk | `KeychainStore.swift` |
| Raw 16 kHz float PCM copy of the call audio during diarization (about 230 MB per hour) | `$TMPDIR/fluidaudio-streaming-<uuid>.raw` | FluidAudio `AudioSourceFactory.swift:89,19-48`; deleted by `defer source.cleanup()` in `OfflineDiarizerManager.swift:153-160` |
| Diarization models (no personal data) | `…/FluidAudio/Models` | FluidAudio |

Observed modes: every Humanity-owned directory is `drwxr-xr-x`, and the files (`mic.m4a`, `meeting.json`, `profiles.json`, `calibration.json`) are `-rw-r--r--`. `tmutil isexcluded …/Humanity` returns `[Included]`. A grep of all app code finds no `posixPermissions`, `setAttributes` or `isExcludedFromBackup`.

What is already good:
- All speech recognition is on-device (`requiresOnDeviceRecognition = true`, `Transcriber.swift:199-202`, `FileTranscriber.swift:86-116`; macOS 26 SpeechAnalyzer). Audio is never sent anywhere.
- API keys are in the Keychain.
- The LLM client uses an ephemeral URLSession with a redirect policy (`LLMClient.swift:51-55`).
- Dictation into a secure-input field skips cleanup, history and audio (`AppModel.swift:262-266,297-299`).
- Dictation paste writes the `TransientType` and `AutoGeneratedType` pasteboard markers (`TextInserter.swift:22-25`).
- Meeting summaries ask once per meeting before going to cloud (`MeetingsView.swift:107-108,217-221`).
- ~/Library is mode 700, so other macOS user accounts cannot traverse into it.

## Findings (ranked)

### 1. Biometric and recording folders are backed up in plaintext, with default permissions (L: M-H, I: H)
- **Scenario.** The victim's Time Machine disk, a NAS, a Backblaze or Carbonite style cloud backup, or a Migration Assistant image holds years of raw call audio, voiceprints, eye patches and transcripts. The disk is lent, sold, stolen or subpoenaed. Backup tools run as the same user, and a backup copy does not inherit ~/Library's 0700.
- **Existing mitigation.** Only `~/Library` being mode 700 and FileVault if the user turned it on. PRIVACY.md does not mention backups.
- **Remaining risk.** Nothing is excluded from backup. Directories are 0755 and files 0644. Any process running as the user can read them, including malware, a compromised Electron app or an AI coding agent. The app is unsandboxed, so there is no container.
- **Fix.** Add one helper in LicenseKit or MeetingKit, say `PrivateFolder.prepare(url)`. It calls `createDirectory(... attributes: [.posixPermissions: 0o700])`. It then sets `URLResourceValues.isExcludedFromBackup = true` on the roots and re-applies both on every launch, which migrates existing installs. Call it from:
  - `RecordingStore.prepare()` (`RecordingStore.swift:24`)
  - `MeetingRecorder.start` (`MeetingRecorder.swift:89`)
  - `VoiceProfileStore.save` (`VoiceProfileStore.swift:188`)
  - `AppPaths.support` (`Persistence.swift:76`)
  - `License.swift:42`, for 0700 only
  Apply the exclusion to the roots `Humanity/Meetings`, `Humanity/VoiceProfiles`, `Murmur/Recordings`, `OculOS` and `OculOS/Recordings`. Do not exclude the license file. Add one PRIVACY.md sentence: "These folders are excluded from Time Machine; a copy you export is not." Say plainly that this also means these items are not restored after a disk failure. Optionally add a Settings toggle "Include recordings in backups". **[ATTY]** Review the wording, since the exclusion changes the user's backup expectations.

### 2. "Delete" does not remove copies, and the retention promises don't match the code (L: H, I: M-H) **[ATTY]**
- **Scenario.** The victim says "I deleted that meeting" or pressed Delete All Data. A pre-existing Time Machine backup, local APFS snapshots (hourly, retained about 24 hours), or a cloud backup still holds the audio. `FileManager.removeItem` unlinks the file only, and it is not a secure erase on APFS or SSD.
- **Existing mitigation.** Delete All removes `OculOS/`, `Murmur/Recordings`, `Humanity/Meetings`, `profiles.json` and the bundle's UserDefaults (`HumanityApp.swift:603-605`; `AppModel.swift:425-438`).
- **Remaining risk:**
  - PRIVACY.md:64 says meeting audio is "optionally automatically after 30, 90 or 365 days". The code only expires `RecordingStore` items (Murmur dictations and notes) at launch (`AppModel.swift:118`), and there is no meeting expiry at all. Meeting `mic.m4a` and `system.m4a` are kept forever, and neither the meeting folder nor the audio is ever pruned. Unmatched speaker centroids expire after 12 months (`Meeting.swift:70-77`).
  - PRIVACY.md:67 says Delete All "erases everything the apps stored". It does not reach backups or snapshots. It leaves `Humanity/license.json` (intended), the FluidAudio models, an empty `VoiceProfiles` folder and the in-memory state of OculOS. Every step uses `try?`, so a failed delete is silent.
  - OculOS saves calibration on a debounced detached task (`GazeEngine.swift:36-46`). That task could rewrite `calibration.json` between the delete and `NSApp.terminate` (low probability).
- **Fix:**
  - Implement meeting retention. In `MeetingsModel.load` (`MeetingsView.swift:~40-50`), delete meeting folders older than `retentionDays`, reusing the existing Murmur setting. If you don't build it, delete the sentence from PRIVACY.md and from the Gumroad copy.
  - Add to PRIVACY.md and to the Delete All dialog: "Deleting doesn't erase Time Machine backups or snapshots already made."
  - Make Delete All report failures (collect the errors instead of `try?`) and cancel any pending `scheduleSave` before removing.
  - Optionally overwrite audio before unlinking. This is of limited value on APFS, so prefer the backup exclusion in #1.

### 3. Crash and force-quit leftovers that nothing lists or sweeps (L: M, I: H)
- **Scenario.** The app crashes, the user force-quits, the battery dies or the Mac kernel-panics mid-call or mid-diarization. The victim later gets a "used"-looking Mac, or repair techs and forensic tools find the leftovers.
- **Existing mitigation.**
  - `MeetingRecording.unprocessed` lists meetings that have a `recording.json` but no `meeting.json`.
  - The comment in `RecordingStore.deleteEverything` notes that audio left by a crash is swept.
  - `defer { source.cleanup() }` deletes the temp PCM on normal exit or throw.
- **Remaining risk:**
  - `recording.json` is written only in `stop()` (`MeetingRecorder.swift:28,135`). A crash during recording leaves `mic.m4a` and `system.m4a` in a folder with no `recording.json`. `unprocessed` skips it (line 35), so the user cannot see or delete it, and only Delete All reaches it.
  - The same applies to a Murmur dictation or note whose `.json` was never saved. `loadAll()` reads only `.json`, so an orphan `<uuid>.m4a` is invisible.
  - On a crash during diarization, `fluidaudio-streaming-*.raw` stays in `$TMPDIR`. It holds uncompressed call audio. It is not in Time Machine, but it stays until macOS cleans `/var/folders` (usually days) and it survives app uninstall.
- **Fix:**
  - On launch, enumerate the Meetings folder and treat any folder with audio but no `recording.json` as unprocessed. Write a stub `recording.json` at `start()` (`MeetingRecorder.swift:~92`).
  - In `RecordingStore.init` or `loadAll`, list `.m4a` files with no matching `.json` (this includes notes with no transcript).
  - At launch, `removeItem` every `fluidaudio-streaming-*.raw` in `FileManager.default.temporaryDirectory`.

### 4. Cloud AI sends other people's words without a per-send prompt (L: M, I: H) **[ATTY]**
- **Scenario.** The victim connects an AI provider key once, for example for dictation polish. After that every dictation (`AppModel.swift:266-272`) and every Library note summary (`AppModel.swift:303,371-380`) goes to the provider silently. Note summaries run automatically. Meeting transcripts carry identified names, for example "Alice: …", from `Transcript.plainText` (`Transcript.swift:81-83`), including names matched from stored voiceprints.
- **Existing mitigation.**
  - Cloud is opt-in per provider key, and there is the secure-field skip.
  - Meeting summaries ask once per meeting (`MeetingsView.swift:107-108`). `cloudApproved` is memory only, so it resets on relaunch.
  - Gumroad text says "only if you add your own key".
- **Remaining risk.**
  - There is no first-use consent screen per provider.
  - Dictation cleanup and note summaries have no prompt at all, and the 2 s dictation timeout hides when a send is happening.
  - There is no way to strip names before sending.
  - The provider's own retention and training terms are outside the app. Some providers store the data for abuse monitoring.
  - Cloud summarize failure falls back to on-device but still sends the transcript first.
- **Fix:**
  - Add a one-time provider-level consent alert in AIKit (`Tasks.route`, `Tasks.swift`). It says what is sent (transcript text and any names), and to whom. Store the approval in UserDefaults.
  - Use the same per-note prompt that meetings use in `AppModel.summarize` (line 371).
  - Add a switch "Replace speaker names with Speaker 1, 2…" that applies to `plainText` before `Tasks.summarize`.
  - Review the recording-consent wording for cloud sends of third-party speech. **[ATTY]**

### 5. Clipboard leaks (L: M, I: M)
- **Scenario.** The victim presses Copy on a transcript, or dictation falls back to the clipboard because Accessibility is missing. A clipboard manager records it, Universal Clipboard syncs it to the iPhone or iPad, or a screen-share leaks it. The text sits there until something overwrites it.
- **Existing mitigation.** Dictation pastes carry `TransientType` and `AutoGeneratedType` (`TextInserter.swift:22-25`), and the previous clipboard is restored afterward.
- **Remaining risk.**
  - The Library copy (`LibraryView.swift:197-198`) and meeting copy (`MeetingsView.swift:304-305`, `MeetingDetailView.swift:33-34`) use plain `setString`, with no transient marker and no timed clear.
  - The `canPaste == false` path (`TextInserter.swift:46-52`) leaves dictation text on the clipboard indefinitely, even in a secure field. The secure-input check comes after it.
  - Whether Universal Clipboard honors these markers I could not confirm.
- **Fix:**
  - Route the copy buttons through `SystemPasteboard.write` (it already adds the markers) and clear after about 60 s if `changeCount` is unchanged.
  - In `insert`, check `IsSecureEventInputEnabled()` first. If it is on, do not write the clipboard.
  - Optionally add `org.nspasteboard.ConcealedType` for sensitive copies.

### 6. Eye patches and optional screenshots on disk (L: L-M, I: M-H)
- **Scenario.** `calibration.json` is a plaintext biometric template: normalized eye-patch pixels (`appearance`), face and head geometry and CNN gaze features. A leaked copy could support face-recognition style attacks or reveal medical-adjacent gaze traits. With "Capture screenshot as heatmap background" on, a full-screen PNG of whatever was on screen is saved next to the gaze trace. That can include passwords, chats or other people's video calls.
- **Existing mitigation.** Screenshot capture is off by default. It needs Screen Recording permission. The UI says screenshots stay on the Mac, and `Clear Calibration` deletes the file.
- **Remaining risk.** Everything in #1 (backups and 0644). There is no warning that a screenshot can contain sensitive content. Screenshots are not excluded from Time Machine.
- **Fix:**
  - Rely on the #1 helper.
  - Add the sentence "Screenshots capture your whole screen, including anything private" under the toggle (`SettingsView.swift:111-113`).
  - Optionally keep `appearance` in memory only unless the user opts in to "Remember calibration".
  - **[ATTY]** Check whether eye-patch pixels count as a biometric identifier or biometric template under Illinois BIPA or Texas CUBI. Voiceprints and eye geometry are on the BIPA list of regulated identifiers. Make sure the retention schedule in PRIVACY.md is enforced in code.

### 7. Voiceprints: plaintext, indefinite until used or unused, kept in two places (L: M, I: H) **[ATTY]**
- **Scenario.** `profiles.json` holds named speaker embeddings, so it is a directory of "who voiced what" for real people. Meeting folders hold centroids too (`diarization.centroids`) until the meeting is 12 months old. A leak of either identifies third parties who never installed the app.
- **Existing mitigation.**
  - Enrolling needs a consent date.
  - Profiles expire after 12 months unused and after 3 years at most.
  - Centroids are dropped when a profile is remembered (`Meeting.swift:63-77`).
  - Deletion exists per profile and in bulk.
- **Remaining risk.**
  - Embeddings are in plain JSON next to the audio, in backups (#1).
  - The 3-year and 12-month rules run only at load (`VoiceProfileStore.swift:76-81`).
  - The app cannot show the third party what is stored.
- **Fix:**
  - Rely on the #1 helper.
  - Optionally move `profiles.json` content into a Keychain-protected blob. That is a bigger change, so leave it for later.
  - Add a one-line "forget this person" action and a PRIVACY.md sentence about erasing a third party's voiceprint on request.
  - **[ATTY]** Consent and retention for third-party voiceprints under BIPA, GDPR Art. 9 and similar.

### 8. Logs (L: L, I: L-M)
- **Scenario.** A victim sends `log collect`, a sysdiagnose or a crash report to support or posts it online.
- **Existing mitigation.**
  - The only app logger writes an integer latency (`AppModel.swift:34,285`).
  - `LLMClient` does not log, and it redacts keys from errors.
  - FluidAudio's `AppLogger` interpolates `\(message)` as a String, so os_log redacts it by default as `<private>` in release builds. Only the warning and error levels are echoed to stderr (`AppLogger.swift`).
  - The offline diarizer logs model paths (which include the macOS user name), timings and counts. It does not log transcripts or audio.
- **Remaining risk.**
  - Humanity never sets `AppLogger.minimumLevel` or `mirrorsToConsole`, so FluidAudio keeps its default debug level. A Debug build prints everything to the console.
  - The path of the diarization temp file appears in an error string on failure (`AudioSourceFactory.swift`).
  - `~/Library/Logs/DiagnosticReports` crash files are written by macOS and stay on disk.
- **Fix:**
  - At launch in MeetingKit, set `AppLogger.minimumLevel = .warning` and `AppLogger.mirrorsToConsole = false`.
  - Mention crash reports in PRIVACY.md.

### 9. Exports leave the protected folders (L: M, I: M)
- **Scenario.** The user exports a transcript or CSV (`LibraryView.swift:202-206`, `MeetingsView.swift:309-317`, `AppModel.swift:358-365`). The save panel often defaults to Desktop or Documents. With iCloud "Desktop & Documents" on, it syncs to Apple servers, other Macs and iOS devices, and it is outside the Time Machine exclusion from #1. The export includes speaker names.
- **Existing mitigation.** The user chooses the location. Nothing else.
- **Fix:** set `panel.message = "This file is a plain copy. iCloud and backups may include it."` on the three panels. Add `panel.directoryURL = ~/Downloads` to avoid the iCloud Desktop default.

### 10. Same-user processes and Spotlight can read everything (L: M, I: M)
- **Scenario.** Any app the user runs (an AI coding agent, a menu bar utility, a malicious download) can read the 0644 files with no prompt, because `~/Library/Application Support/<third-party>` is not a TCC-protected location.
- **Existing mitigation.** None beyond ordinary macOS user separation.
- **Remaining risk.**
  - No sandbox and no encryption at rest.
  - Whether Spotlight indexes the JSON transcripts I could not verify. Add `.metadata_never_index` to the folders if it does.
- **Fix:** the 0700 change in #1 narrows nothing against same-user processes. The real fix is large (App Sandbox container, or encrypting the files with a Keychain key), so list it in SECURITY.md as a known limitation: "Humanity's data is readable by any program running as you".

### 11. Ad-hoc unnotarized builds and update trust (L: L, I: H)
Not an exposure path in itself. The Gumroad 5-step Open Anyway flow trains users to bypass Gatekeeper. A tampered download would have mic, camera and Accessibility access. Existing mitigation: LICENSE and `scripts/` show ad-hoc signing only. Fix: publish SHA-256 checksums with each release and say so on the product page. **[ATTY]** Review how "no analytics, no telemetry" is worded next to the licence check.

### 12. Licence check is the only network call with a user-identifying key (L: L, I: L)
`license.json` holds the Gumroad key. The key links the exposure victim to a purchase (email). Existing mitigation: it is a licence receipt, not recording data. Fix: nothing needed. State in PRIVACY.md which data the licence check sends. **[ATTY]** Privacy-policy accuracy.

## Minimal change set (in priority order)

7. Warn on export and screenshot capture. (#9, #6)
